# 2026-11-12 设计：把「要不要问人」挪到回合末

在此之前的所有修正（去重、不静默、过期收尾、脱敏）都只是让提问**变得干净**，
没有解决「问得对不对」。这份文档用真实账本给出证据，并把改动落成分三步可验证的方案。

## 1. 证据（真实账本，2026-11-11 ~ 11-12）

| 指标 | 实测 | 含义 |
| --- | --- | --- |
| `asks.json` 条目 | 6 | 全部来自闸门（不可逆动作） |
| 其中人真正作答 | **0** | 人一次都没有回答过 |
| 其中由默认答案收尾 | **6（100%）** | 4 条过期收尾（6h）+ 2 条超时继续（10min） |
| 卡片总数 | 86 | — |
| `interaction=question`（把会话卡住的提问） | **3** | 真正的「打断」只有 3 张 |
| `interaction=reply`（一轮结束后的记录） | 83 | 卡片绝大多数是**记录**，不是提问 |
| 已收尾但没有任何人工动作的卡（zeroAction） | 60 / 86 = **69.8%** | 七成卡片不需要人 |
| 人工动作次数 | 约 26 | 覆盖 97 个真实回合 |

**结论一**：闸门在**工具调用前**判断「要不要问」，转化率是 **0/6**——问的六次全都白问。
**结论二**：卡片的主要体量不是打断，而是「一轮结束后的记录」，人却要按卡片数去浏览。
**结论三**：真正把会话卡住、值得人看一眼的，只有 3 张。

所以问题不在卡片机制，而在两点：
1. **判断的时机**：事前判断只有一行命令字符串，信息量最少，误报必然高；
2. **记录的粒度**：过程记录也进卡片，等于把日志混进了收件箱。

## 2. 设计（P4：回合末收口）

核心一句话：**闸门只判「可逆 / 不可逆」，不再判「要不要问人」；提问在回合末由执行方提出，
闸门负责兜底保证不漏。**

```
工具调用 ──► 闸门分类
             ├─ 可逆 ─────────────► 放行 + autonomy:auto 审计（现状，保留）
             └─ 不可逆 ──► deny + 预登记 pendingAsk（判据/回滚点/默认答案/身份键）
                                │
                       回合末（turn/end）
                                │
             ┌──────────────────┴──────────────────┐
     执行方按格式自述了 ask              没自述
     （措辞带业务背景与选项）        （预登记那张兜底）
             └──────────────────┬──────────────────┘
                        目标内合并为 **1 张**
```

四条硬约束：

- **零静默**：预登记一定会在回合末落地，不管执行方说没说。被拒、被去重、被吞都要能被数出来；
- **幂等**：`(goalId, 身份键)` 是唯一键，同一动作重试不产生第二张；
- **一目标一 ask**：同一目标内的多个 pendingAsk 合并成一张多问题卡（面板已支持逐题作答）；
- **可回退**：`autonomyMode=supervised` 仍走旧路径（闸门直接建卡），随时切回。

## 3. 三步实施（每步独立可验证）

| 步 | 内容 | 验证 |
| --- | --- | --- |
| S1 | 新增 `pendingAsk` 存储（内存 + 落盘），闸门不可逆分支改为「deny + 预登记」，不再直接写 `asks.json` | 单测：同一身份键两次 → 1 条；回合末 flush → 1 张卡；`/stats.noise.asks` 不变 |
| S2 | 接 `turn/end`：flush 预登记（执行方若有结构化 ask 则采用其文本），同目标合并 | 集成：一次回合里 3 次被拒 → 恰好 1 张卡，正文含三条判据 |
| S3 | 过程记录降级：`interaction=reply` 且 zeroAction 的卡不再进「待处理」车道，只进「记录」视图 | `/stats.noise.cards.zeroActionRate` 下降；面板默认视图只剩需要人的卡 |

## 4. 验收指标（当前基线 → 目标）

| 指标 | 现在 | 目标 |
| --- | --- | --- |
| `noise.asks.autoRate`（默认收尾占比） | 1.0 | ≤ 0.3（问的十次里有七次是人真答的） |
| `noise.cards.zeroActionRate` | 0.698 | ≤ 0.35 |
| 卡 / 目标 | 0.6 | = 1（一目标一结果）+ ≤1 ask |
| 真正打断（`interaction=question`）/ 回合 | 0.031 | 不升高（3/97 已经很低） |
| 零静默（被拒动作未落地的条数） | 未度量 | = 0，且 `/stats` 可见 |

## 5. 风险

- **执行方不配合**：它可能被拒后换一条路绕过。→ 兜底卡保证人一定看到；同时 deny 文本明确写「已登记，
  回合末会问你，不要换路径规避」。
- **回合末没有可靠信号**：宿主 `turn/end` 是我们已经有的事件（回合计数就在用它），缺信号时退化为
  定时 flush（30s），仍然零静默。
- **合并过度**：同一目标三件不相干的事被压成一张卡会难答。→ 合并上限 5 题（面板逐题作答已支持），
  超过则拆第二张。

## 6. 与既有工作的关系

- 已完成的 P1（可逆放行 + `autonomy:auto` 审计）是这套方案的前半段，**不用改**；
- 已完成的去重 / 过期收尾 / 脱敏是兜底层，继续生效；
- 本次只新增 S1–S3，不改卡片状态机与契约字段，`supervised` 模式保持可回退。
