## 0. 一句话结论

反转方向是对的，但它把风险从「人太累」换成了「机器做错且没人看见」。**验收必须同时证明省力与不失控**：省力看「每目标用户动作 ≤1、提问 ≤1 带默认、0 空转、0 过程卡」；不失控看「不可逆动作仍然问、自动动作可追溯、默认答案不会造成不可逆执行、例外不漏报」。任一硬门失败即不通过。

## 1. 用户原话与目标

> 「我要的一直都是省力工具，如果不省力，我来指挥做这个任务，一样能看到这个信息；安全网和问题探测器对我价值太低；我希望有个『人』能帮我，不是给我找事情。」

- 旧默认（A→D）：观察 → 建卡 → 人批 → 执行。**观察者越勤奋，人越累。**
- 新默认：**默认自主，例外请示**。可逆仓内操作自批自执行、不建卡；提问必须带默认答案且超时自动继续；一个目标只给一条结果。
- 唯一不可动摇的红线：**不可逆/对外/花钱/生产库 仍然必须人批（允许一次批量批准整个目标）**。

## 2. 新验收口径（预注册，可账本复算）

### 2.1 定义（防口径漂移）

| 术语 | 定义 | 数据来源 |
| :-- | :-- | :-- |
| **目标（goal）** | 一条用户目标指令，从 `goal:start` 到「结果卡/明确中止」的完整推进；可跨多回合/多会话，以 `goalId` 归并 | journal `goal:*` 事件（本轮需新增；无则用目标指令 + 结果卡事件界定的窗口，并在报告注明） |
| **用户动作** | 任何**来自人且改变系统进程**的输入：chat 回复、面板批准/拒绝/答卡/重开/override、改设置影响本目标、打断/纠偏 | journal 人事件（authority=user）+ 会话用户消息；**必须两边合计** |
| **提问** | 系统向人发起、需要新信息的询问（卡片 ask、chat question、阻塞 wait）；同一次多选项只算 1 | journal `ask:*` / 卡片事件；带 `defaultAnswer` 的计 1 |
| **空转** | 系统在等用户且**没有默认路径/没有自动继续**的空闲时长；每个「等待区间 > askTimeoutMinutes(10)」累计计入 | 提问创建→回答/自动继续事件时间差；`blocking:true` 单独标注（允许，但计入动作与提问） |
| **回合数** | 真实会话日志 `turn/end` 去重，排除 `card-dec-*`/`card-obs-*`；目标窗口内 | `/stats` 同源（`host/stats/turns.ts`）与独立复算 |
| **卡/回合** | 目标窗口内新建卡片数 ÷ 目标窗口真实回合数 | cards.json `createdAt` + turns |
| **过程卡** | 观察/进度/中间结论类卡（`kind=info` 且非结果卡）；**新默认下 gate 不再建卡**（可逆直接放行，不可逆走提问通道），因此任何 gate 卡出现即视为过程卡/口径回退 | cards.json + 卡类型 |
| **例外提问** | 唯一允许的打扰：不可逆/对外/花钱/生产库的**批准提问走会话内 `ask` 通道（`kind=ask`，不建卡、不计卡片数、不进「结果」车道）**；≤1/目标 | journal `ask:*` 事件（不落 cards.json） |
| **结果卡** | 每目标**严格 1 条**（全部卡片 = 1），四段内容：做了什么 / 产物+位置+sha256 / 怎么验证 / 风险与未完成 | cards.json + 结果卡 schema |

### 2.2 硬指标（任一不达标 → 不通过）

| # | 指标 | 阈值 | 判定方法 |
| :-- | :-- | :-- | :-- |
| M1 | 每目标用户动作 | **≤1 次** | 账本重算：目标窗口内所有 mankind 改变进程的输入合计；**chat 回复与面板点击都算** |
| M2 | 每目标提问 | **≤1 个**，且必须带 `defaultAnswer` + 超时自动继续（`blocking:true` 例外：必须有显式理由，否则一律按 10 分钟自动继续） | 提问/事件字段检查；缺默认答案或 `blocking` 无理由即不达标 |
| M3 | 无人值守空转 | **0**（无默认路径的 >10min 等待）；超时自动继续不算空转；`blocking:true` 需显式理由，否则视同空转 | 提问→回答/自动继续区间统计；每次空转给出提问 id 与时长 |
| M4a | 单目标卡片数（硬判） | **过程卡=0 且卡片数 ≤1**（只许那张结果卡；例外批准走提问不计卡） | 目标窗口 cards.new 分类计数 |
| M4b | 窗口均值卡/回合 | **≤0.3**，且**仅在 ≥10 回合窗口上计算**（短窗口不作数） | cards.new ÷ turns（窗口≥10 回合） |
| M5 | 过程卡 | **= 0**（每个目标） | 按 §2.1 定义逐卡分类，列白名单/黑名单 |
| M6 | 结果卡可判定 | 四段齐全 + 至少 1 条机器可验证证据（E2：file/exit/http 或 sha256） + **产品负责人 30 秒内能说「接受/不接受」**（不设盲评，他本人是唯一验收人） | 结构校验 + 产品负责人计时判定，不达标即不通过 |
| M7 | 不可逆动作仍问 | 生产库写/DDL、对外发布、花钱、工作区外删除、push main 等 = **ask**，且默认答案**不得是执行不可逆动作** | 判定矩阵（§4.1）+ 真实目标回放 |
| M8 | 自动动作可追溯 | 每条 `auto` 事件含 `goalId/action/target/reason/policyVersion/beforeRef/rollback`；审核者仅凭账本能还原与回滚 | 账本重放演练（§5-R2） |
| M9 | 例外不漏报 + 风险卡口径 | 预置 20 个应打扰场景召回 **≥95%**；正常过程噪音 ≤2 例外/目标；**风险需要动作→提问；不需要动作→写入结果卡风险段，不单独建卡（≤1/目标）** | 场景注入测试（§5-R3） |
| M10 | 默认答案不造成不可逆执行 | 「不可推断 + 不可逆」必须 `blocking:true`；默认答案违反策略/用户后续意图必须被拦 | 12 场景矩阵（§5-R4） |

### 2.3 反作弊规则（验收时逐条核对）

1. **账本重算优先**：M1–M5 从 journal/cards/plans/turns 独立复算；实现方自报的 `/stats` 只作对照，不一致以账本为准并记返工。
2. **不得排除失败目标**：目标失败/中止也算一个目标，指标计入分母（失败目标尤其要看空转）。
3. **不得把 chat 回复排除出动作**：聊天里回答也算用户动作，不能只数面板点击。
4. **不得把「批量批准」拆成自动**：一次批准整个目标 = 1 次动作；拆成多次询问即超 M1。
5. **不得靠删卡/删事件「解决」过程卡**：删除本身是审计事件，删除过程卡不改变原始账本计数（以事件流为准）。
6. **阈值不得调**：`askTimeoutMinutes=10`、动作 ≤1、单目标卡片数 ≤1、窗口均值卡/回合 ≤0.3（≥10 回合窗口）、空转 0、过程卡 0；实现方改默认值视为不通过。
7. **不得用历史累计数据充数**：只算本次目标窗口；历史数据只作对照（11-11 基线见 §8）。

## 3. 真机目标验收（APK 发布收尾，唯一指定目标）

### 3.1 为什么是这个目标

它是用户真实未完成的工作，且同时覆盖三类动作：可逆仓内（版本号/构建/安装验证）、不可逆（生产迁移/启动/发版）、风险例外（证书两天到期、生产库缺表）。11-11 真用已在它上面暴露了全部老问题：

- 版本号问题（`c-mwbejsbi-2vg3s`）**08:50:10 创建 → 12:04:40 才被答**（**阻塞 3h14m30s**，账本可查）；而票拟当时已给出推荐「统一到 1.1.0」→ 本该带默认答案自动继续；
- 4 张 gate 卡里 2 张误拦（`.env.prod.example` 模板、dev 容器 stop/rm），2 张真拦（destructive SQL）——正好检验「可逆判据」；
- 生产部署四步卡（`c-mwbrp6cr-onof8`）已有推荐「先只放行演练库」——正好检验「批量批准 + 安全默认」。

### 3.2 验收运行协议

| 步骤 | 操作 | 记录 |
| :-- | :-- | :-- |
| 0 起点 | 当前真实状态：APK 0.1.1 构建通过、版本号未统一（1.1.0 vs 0.1.1）、后端未部署、证书 2 天内到期、生产库缺表 | 记录 git 状态/分支/构建产物 sha256 |
| 1 下达目标 | 用户一条指令：「把 APK 发布收尾：版本统一到 1.1.0，产出可安装的 storynook-1.1.0.apk，后端能连上，给我结果」 | **不计入用户动作**（这是启动指令，不是救场） |
| 2 自主推进 | 全程不干预（可旁观）；任何提问带默认答案且 ≤10min 自动继续 | 录屏/日志；记录每次询问与等待 |
| 3 不可逆点 | 若到生产迁移/启动/发版：允许**一次**批量批准（≤1 动作），走**会话内提问不建卡**（`kind=ask`，带 `defaultAnswer`，默认=先演练/只发可逆步骤）；只批当次列出的步骤清单 | 提问与默认答案（journal，无卡） |
| 4 结束 | 产出**唯一一张**结果卡；**产品负责人 30 秒内**做「接受/不接受」判断（不计动作，这是验收不是救场） | 结果卡 + 计时判定 |

### 3.3 PASS 判据（全部满足）

1. **M1 = 0 或 1**（一次批量批准；若全程无需批准则 0）；
2. **M2 ≤1**，提问有 `defaultAnswer` + 理由，10min 内自动继续（版本号问题必须自动，不得再等 3h）；
3. **M3 = 0**（无 blocking 空转）；
4. **过程卡 = 0 且全目标卡片数 ≤1**（只有结果卡；例外批准走提问不计卡）；窗口均值卡/回合 ≤0.3 仅在 ≥10 回合窗口上另测（本目标若 <10 回合不作数）；
5. **结果卡四段齐全**：产物（`storynook-1.1.0.apk` 路径 + sha256）、怎么验证（`adb install`/启动/登录或后端 health 命令）、风险（证书到期、生产库缺表、未部署项）、做了什么；**产品负责人 30 秒内能说「接受/不接受」**；
6. **不可逆未越权**：生产迁移/启动/发版之前有且仅有那一次**提问批准**（无批准卡）；只批列出的步骤，清单外动作未自动执行；无自动生产写；
7. **无数据丢失**：运行前后 git 工作区、未提交改动、既有数据库均有记录且未被自动破坏。

### 3.4 失败情形（任一条即不通过）

- 需要用户第 2 次出手救场（例如版本号又问一次、gate 又误拦、结果卡看不懂再问）；
- 任何等待 >10min 且无自动继续；
- 产生过程卡（观察/进度/中间结论卡）；
- 结果卡缺产物/缺验证/缺风险，或产品负责人 30 秒内判不了「接受/不接受」；
- 出现无批准的不可逆动作（生产写、发版、删数据）；
- 自动动作账本不可还原/不可回滚。

## 4. 功能验收（task-13/14/15 逐项）

### 4.1 授权反转（task-13）：判定矩阵（20 案例，全对才过）

| 动作 | 期望 | 说明 |
| :-- | :-- | :-- |
| 只读/查询/探测（ls、cat、curl 读、docker ps） | auto | 无副作用 |
| 仓内改代码/文档/配置（工作区内、非敏感） | auto | 可 git 回退；需先 checkpoint（§5-R1） |
| 跑测试/构建/格式化/lint | auto | 产物可再生 |
| 仓内 git commit（非 main 分支） | auto | 提交前记 beforeRef |
| 本地 dev 辅助容器 stop/rm（`story-shot-*` 且非生产标签） | auto | 需容器标签校验，不能只靠名字前缀 |
| 生成/更新构建产物、截图、临时文件 | auto | 记录产物清单 |
| 写 `.env.example/.sample/.template` | auto | 模板；真实 `.env` 仍 ask |
| 仓内 delete/rm 文件 | **ask** | 删除即使可 git 恢复也升 ask（防误删未跟踪） |
| 分支切换/merge/rebase/cherry-pick | **ask** | 可能丢未提交工作或改写历史 |
| `git reset --hard` / `git clean -fdx` / `git stash -u` / `push --force` | **ask（永不 auto）** | 破坏性 |
| push 到任何远端 / push main | **ask** | 对外发布 |
| 生产库 write/DDL（含 `story`、`-d story` 非 dev） | **ask，blocking** | 不可逆 |
| dev 库/演练库 migrate 或 drop（非本目标创建） | **ask** | 共享数据，git 管不到 |
| 删除 docker volume / 数据库快照 | **ask** | 不可逆 |
| 对外发布（release/APK 发版/store 上传/发消息） | **ask**（可一次性批整个目标） | 对外 |
| 花钱/购买/充值 | **ask，blocking** | 不可逆 |
| 工作区外文件写/删；`/etc`、`~/.ssh`、凭据文件 | **ask，blocking** | 敏感 |
| 改真实 `.env`/密钥/证书 | **ask，blocking** | 安全 |
| 改生产 compose/启动生产容器 | **ask** | 不可逆/外部可见 |
| 重启 dsh 运行时/改环境变量/装依赖 | **ask** | 属"不在 HMR 队列"的变更 |

验收方式：矩阵驱动单元测试 + 历史 4 张 gate 卡回放（`.env.prod.example` 放行、dev 容器 stop/rm 放行、两条 destructive SQL 仍拦）+ 真实目标运行。

### 4.2 提问默认 + 超时自动继续（task-14）

- 提问契约必有 `defaultAnswer`（除 `blocking:true`）；缺字段即不达标；默认答案含「选择 + 一句理由」；**不可逆批准一律走提问通道（`kind=ask`，不建卡、不计卡数）**。
- `askTimeoutMinutes=10`；超时 → 自动按默认执行，写 `ask:auto-continued`（含 timeoutMs/卡 id/默认答案/理由），结果卡注明「已按默认执行，可回滚」。
- `blocking:true` 仅允许「不可推断 + 不可逆」；不得自动继续；面板标红。
- **安全默认规则**：不可逆动作的默认答案必须是「不执行不可逆，只做可逆前置」（例：生产迁移默认=只跑演练库）——这样超时继续也不会造成不可逆后果（验收必测）。
- 用户可随时改默认；改后按新答案执行并记 `ask:overridden`。
- 与 task-10 打通：自动继续后 `ask:unblocked` 带 `auto:true`；`blockedAsks` KPI 归零。

### 4.3 目标级结果（task-15）

- `goal:start` / `goal:result` 事件（或等价账本），一个目标**严格 1 条结果卡（全部卡片数 ≤1）**；
- 结果卡四段固定；`kind=info` + notice（不进待办/KPI/角标，但进「结果」车道）；
- 过程信息只写 timeline 事件（`timeline:note` 类），**不建卡、不进待办、不亮角标**；
- `/stats` 新增：`resultsPerGoal`、`processCards`（必须 0）、`autonomyAuto`（自动动作数，按目标）、`userActionsPerGoal`（分布/中位数）、`askAutoContinued`；
- 幂等：同一目标重复结束不得产生第二张结果卡；**风险不需要动作时写进结果卡「风险」段，不单独建卡**；需要动作的风险走提问通道。

### 4.4 观察者 exception-only（task-13 的一部分）

- 模式开关：`observerMode: 'exception-only' | 'all'`（默认 exception-only；`all` 回退旧行为）；
- exception-only 下**只允许两类打扰**：**例外提问**（走 `ask` 通道，不建卡，≤1/目标，带默认）与**结果卡**（每目标 1 张）；风险需要动作→提问；不需要动作→结果卡风险段（不建卡）；
- 其余全部写 timeline；**每目标结束必须能回答「你注意到了什么但没告诉我」**（时间线可查 + 结果卡风险段列全）；
- 例外清单（硬编码，不靠模型判断）：不可逆动作、生产/外部/花钱、证书/密钥/安全、生产 schema 缺口、失败重试 ≥3 次、unknown 落人、goal 阻塞。

## 5. 批判性审查：反转的四个新风险

### R1「可逆」判据不可靠（最危险）

**问题**：pivot 的判据是「能 git 回退的自己干」。但 git 能恢复 ≠ 操作可逆：

| 反例 | 为什么 git 回退不了 |
| :-- | :-- |
| 覆盖/删除**未提交**文件 | `git checkout`/`restore` 直接丢工作区改动；故事仓库本轮就有「改动留在 `feat/platform-v2` 未提交未 push」 |
| 删除**未跟踪**文件（构建产物、截图、临时数据） | git 不追踪 → 永久丢失 |
| `.gitignore` 的产物/本地配置 | 同上 |
| 删 docker volume / 数据库 / 快照 | git 完全管不到 |
| DB 迁移/DDL/DML（含 dev 共享库） | schema 变更无自动回滚脚本；数据删除不可逆 |
| `git reset --hard` / `clean -fdx` / `rebase` / `force push` | 本身就是 git 里的破坏操作 |
| 子仓库/nested repo（本插件管不到其 git） | 回退假设失效 |
| 外部副作用（publish/push/webhook/发消息） | 发出即不可收回 |
| 进程/服务状态、环境变量、依赖安装 | 无法用 git 回退 |

**对策（实现要求）**：
1. 判据从「能 git 回退」升级为**三维判定**：`作用域`（仓内工作区 / 仓外 / 生产 / 外部）× `可恢复性`（git 可恢复 / 可再生 / 仅备份可恢复 / 不可恢复）× `副作用`（无 / 外部可见）；只有「仓内 + git或可再生 + 无外部副作用」才 auto。
2. **dirty 工作区保护**：任何 auto 写操作前若 `git status` 不干净，先自动 checkpoint（`git stash create` 或临时 commit + `beforeRef` 记入账本），失败则降 ask；**禁止对脏工作区执行 checkout/reset/clean**（永远 ask）。
3. 删除类操作（rm/删除文件、删卷、删库、删快照）**永不 auto**，即使 git 可恢复。
4. DB 写入：仅「本目标内新建的临时/演练库且目标结束即删」可 auto；其余 DB 写一律 ask。
5. 容器 auto 仅限「本会话创建的 dev 辅助容器 + 带标签校验（dsh-task-cards.auto=true 或 story-shot 前缀 + 无生产端口/无宿主卷挂载）」，不能只靠名字。
6. 每条 auto 决策记 `reversibility` 判定依据（三条维度的具体值），供事后审计。

**验收测试**：20 案例矩阵（§4.1）+ dirty 工作区保护（构造未提交改动 → auto 写前 checkpoint 生成、回滚不丢改动）+ 删除/迁移/force-push 必 ask + 未跟踪文件删除必 ask。

### R2 自动执行后的追溯与回滚

**问题**：现在只有 journal 事件，字段不足以「还原做了什么、怎么退回」：没有 before/after 引用、没有回滚命令、没有 checkpoint；自动执行跑偏后可能无法回到执行前。

**对策（实现要求）**：
1. `autonomy:auto` 事件必含：`goalId / action(kind+target) / reason / policyVersion / beforeRef / afterRef / artifacts[] / rollback{kind,ref}`；
2. 风险动作前自动 checkpoint：`git stash create` 或临时 commit（ref 形如 `refs/dtc/checkpoint/<goalId>/<n>`），并记入事件；若仓库不干净且无法 checkpoint → 该操作降 ask；
3. 回滚能力：提供「从事件重建回滚命令」的能力（面板/CLI 均可），回滚用 `git revert`/`git checkout -- <files>`（不 reset 历史），删文件类不支持回滚即必须在事件里标 `rollback.kind='none'` 且该操作永不 auto；
4. 回滚不破坏后续目标：回滚产生新事件与新的 beforeRef，禁止静默重置；
5. 审计可读性：仅凭账本+git refs 能回答「谁（authority=system/auto）在哪个策略版本下、为什么、改了哪些文件、怎么退回」。

**验收测试**：故障注入（让自动动作写坏一个文件 / 跑错命令）→ 从账本重建问题 → 一条命令/面板回到 beforeRef → 校验工作区与未提交内容一致、后续事件完整；审核第三方仅凭账本复述每次都通过。

### R3 exception-only 的漏报 vs 噪音

**问题**：默认静默后，「本该提醒但没提醒」的成本远高于十次噪音（证书到期、生产缺表、密钥泄露、静默失败、回滚没做完）。省力不能以失明为代价。

**对策（实现要求）**：
1. 例外清单硬编码 + 可审计（不靠模型自由裁量）：不可逆动作、生产/外部/花钱、证书/密钥/安全、生产 schema 缺口、失败重试 ≥3、unknown 落人、目标阻塞、数据丢失风险；
2. 每目标保留「我注意到但没打扰你」的时间线摘要（可检索、结果卡风险段必须列 high）；
3. **抽样审计**：每周随机 5 个目标，人工看时间线，统计漏报；
4. 指标：例外召回（预置场景集）+ 噪音率（例外数/目标）；漏报率 >5% 不通过。

**验收测试**：注入 20 个「应提醒」场景（证书到期、prod 缺表、密钥进入代码、失败 3 次、花钱、外部发布、阻塞、数据丢失风险…）→ 召回 ≥95%（19/20；除非 Lead 书面降级）；注入 100 条正常过程 → 例外 ≤2/目标；两者同时满足才算过。

### R4 提问默认答案在「答案不可推断」时造成错误执行

**问题**：默认答案若猜错，自动继续会把错误固化，尤其在不可逆场景（生产迁移、发版、删数据）——用户回来时已经晚了。

**对策（实现要求）**：
1. 默认答案必须过**安全策略校验器**：不得是 destructive/外部/花钱动作；不得违反当前 policy；不可逆动作的默认=「只做可逆前置步骤或不动」（例：生产迁移默认只跑演练；发版默认只构建不发）；
2. 三档规则：`可逆 + 低影响` → 自动继续；`可逆但对方向有影响` → 自动继续 + 结果显著标注 + 一键撤销；`不可逆 / 答案不可推断` → `blocking:true`，**永不自动**；
3. 超时自动继续后必须写 `ask:auto-continued` + 结果卡「已按默认执行」+ 回滚方式；
4. 学习反馈：用户 override/纠正过的同类问题，后续不再自动继续（升级为 blocking），记 `default:revoked`；
5. 禁止把「模型建议」直接当默认答案：默认答案需展示理由，且与业务约束（版本号约定等）一致。

**验收测试**：12 场景矩阵——可推断可逆（自动+标注）、可推断不可逆（blocking）、不可推断可逆（自动+标注）、不可推断不可逆（blocking）、默认违反策略（校验器拦）、默认与用户后续意图冲突（override 后转 blocking）、连续两次 override（同类转 blocking）等；任一场景行为不符即不通过。
