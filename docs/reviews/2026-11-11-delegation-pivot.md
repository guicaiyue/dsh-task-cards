# 方向反转：从「整理你的决定」到「替你决定」（2026-11-11）

> 触发：产品负责人在真用一轮后指出——「如果不省力，我来指挥做这个任务，一样能看到这个信息；我要的是有个『人』能帮我，而不是给我找事情。」
> 结论：A→D 做的是「把人的决定整理成卡片」（决策流水线），而用户要的是「把人的活接过去」（委托机器）。本文是反转方案，A→D 的结构保留为底座，但**默认值全部反过来**。

---

## 1. 错在哪（一句话）

A→D 把「观察 → 建卡 → 人批 → 执行」当成了默认路径。于是每件事都变成一张需要人看的卡：
**观察者越勤奋，人越累。** 真用数据：15 张卡 / 4 回合，我做了 14 次动作，其中真正需要判断的只有 2 次。

## 2. 反转后的默认路径

```
用户给目标
   ↓
会话 agent 自己规划（内部 plan，不建卡）
   ↓
自批自执行（可逆、仓内、可回退）
   ↓
自验收（跑测试/检查产物）
   ↓
只在两种时刻找用户：
   A. 目标完成 → 一条结果（文件/链接/sha256/截图）
   B. 真卡住或要碰不可逆 → 一条问题，且自带默认答案
```

**卡片不再是人机之间的收费站，而是例外通道 + 审计日志。**

## 3. 授权策略反转（核心）

| 动作类型 | 旧默认 | **新默认** |
| :-- | :-- | :-- |
| 只读、查询、探测 | 自动 | 自动 |
| 仓内写代码 / 改配置 / 跑测试 / 构建 | **建卡等人批** | **自动自批自执行** |
| 仓内 git 提交（非 main） | 建卡 | **自动**（main/push 仍需批准） |
| 本地容器 stop/rm（dev 辅助容器） | 建卡 | **自动** |
| 生产库写 / DDL | 建卡 | 建卡（**必须人批**） |
| 对外发布（release/发版/发消息） | 建卡 | 建卡（**必须人批**，但一次性批整个目标） |
| 花钱 | 建卡 | 建卡 |
| 不可逆删除（工作区外、生产数据） | 建卡 | 建卡 |

判据一句话：**能 git 回退的，自己干；不能回退的，问一句。**

## 4. 问题自带默认（消灭空等）

- 任何要问用户的问题，卡上必须给 **「默认答案」**（agent 自认为最合理的选择）；
- 超过 `askTimeoutMinutes`（默认 **10**）无回复 → **按默认答案继续**，并在结果里注明「已按默认执行，可回滚」；
- 只有在「答案不可推断 + 后果不可逆」时才允许无限等待（`blocking: true` 显式标注）。

真用教训：版本号问题空等 3h18m，而它完全可以自己定（沿用 0.1.x 约定）。

## 5. 报告降噪（一目标一结果）

- 过程信息进**时间线事件**，不建卡、不进待办、不亮角标；
- 目标结束时给**一条结果**：做了什么、产物在哪、怎么验证、有什么风险；
- 风险类（证书到期、生产缺表）保留独立卡且 `severity=high`——这是唯一必须打扰的类别。

## 6. 省力的可测标准（新验收）

| 指标 | 现状 | 目标 |
| :-- | :-- | :-- |
| 每个目标的**用户动作次数** | 14 次 / 4 回合 | **≤1** |
| 每个目标的**提问数** | 4（其中 2 个可自决） | **≤1，且带默认答案** |
| 无人值守时长 | 3h18m 空转 | **0**（超时按默认继续） |
| 卡片/回合 | 3.75 | **≤0.3**（只有例外与结果） |
| 结果可验证性 | 报告散落 | **每条结果带产物+校验方式** |

**判据：如果一件事我能用一句命令自己推进，插件就不该为它生成任何卡片。**

## 7. 保留什么（不推翻 A→D）

- 契约对象、三账分离、决定状态机、plans.json、幂等/租约/重试：**底座保留**；
- 闸门：保留，但只拦不可逆；
- 观察者：保留能力，但**默认只产出「例外/风险/结果」三类**；
- 决策代理人：从「出票拟等人批」变为「**自批 + 记录 rationale**」，人可事后审计与 override。

## 8. 落地顺序

1. **P1 授权反转**（最重要）：策略表 + `autoApprove` 扩展到「可逆仓内」，观察者默认只管例外/结果；
2. **P2 问题默认 + 超时继续**：卡带 defaultAnswer，超时自动继续并标注；
3. **P3 目标级结果**：一个目标一条结果卡，过程进时间线；
4. 用真实目标实测（APK 发布）：验证「用户动作 ≤1」。

---

## 9. 口径裁决（2026-11-11 15:40，按审计员 §7 提案）

审计员指出 M4「卡/回合 ≤0.3」与「不可逆必须批准」自相矛盾（含批准的目标至少 2 卡，短窗口下必然 >0.3）。裁决如下，**定了不再改**：

### 9.1 采用方案 (b)：例外批准走提问，不建卡
- 不可逆动作的批准走**会话内提问**（带 `defaultAnswer`），**不生成卡片**；
- 一个目标结束时**只留 1 张结果卡**；
- 因此 M4 改为两条：
  - **单目标硬判**：过程卡 = 0，卡片数 ≤ 1（结果卡）；
  - **窗口均值**：卡/回合 ≤0.3（仅在 ≥10 回合窗口上计算，避免短窗口噪声）。

### 9.2 其余口径
| # | 裁决 |
| :-- | :-- |
| M1 | 启动指令不计入用户动作；chat 回复与面板点击都算 |
| M3 | 超时自动继续后不算空转；`blocking:true` 的等待需要显式理由，否则一律 10 分钟 -->
| 批量批准 | 只批当次列出的步骤清单，清单外不可逆动作必须重新问 |
| askTimeoutMinutes | 固定 10 分钟 |
| M6 盲评 | 不设 2/3 盲评；**产品负责人 30 秒内能说「接受/不接受」**即达标（他本人就是唯一验收人） |
| M9 风险卡 | 风险**需要动作** → 提问；**不需要动作** → 写进结果卡「风险」段，不单独建卡（≤1/目标） |
| supervised 开关 | 保留但降级为高级设置，默认 `auto` |
| M8 自动动作 | 事件必须含 `goalId/action/target/reason/policyVersion/beforeRef/rollback`；删除类永不 auto；dirty 工作区先 checkpoint 否则降 ask |

### 9.3 对实现（task-13/14/15）的直接影响
1. **例外提问不建卡**：`ask` 档走 `ask` 通道（卡可复用但 `kind=ask`、不计卡片数、不出现「结果」车道）；
2. **结果卡严格 1 张/目标**；
3. 自动动作必须写 `beforeRef`（checkpoint ref）+ `rollback` 字段；
4. 风险若需要动作，作为提问而非风险卡。
