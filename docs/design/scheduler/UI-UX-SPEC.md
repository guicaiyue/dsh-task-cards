# 交互细化：历史、会话区分、权限、设置与会话内介入

> 承接 [A-core 方案](A-CORE-PLAN.md) 的 §5（前端）与 §4.5（决策策略）。本文只谈**交互与信息架构**，不新增运行时概念；所有状态都能映射回 A-core 的 Case / Verdict / Plan / Result / Outcome。
> 原则三条：**可解释**（每个"等一下"都有原因）、**可撤回**（能撤销的才敢自动化）、**可扩展**（加卡/加规则不改版式）。
> 2026-11-08 决策：`unknown` 先由决策者判重试/补偿，判不了再升级用户；面板四周不留宿主底色边。
> 原型已同步：见 [prototype/](prototype/) 与 [OpenDesign 项目](http://127.0.0.1:7456/projects/dsh-task-cards-scheduler-ui/conversations/ff0718c3-5f64-4646-8faa-240a05d27dbf/files/index.html)（记录 / 设置 / 会话三屏为本轮新增）。

## 0. 信息分层（先定层级，再谈页面）

| 层 | 回答什么 | 出现位置 | 默认展开 |
| :-- | :-- | :-- | :-- |
| L0 概览 | 现在有几张卡、分别卡在哪 | 工作台 KPI + 过滤 | 是 |
| L1 卡片 | 这张卡是什么、谁批的、现在什么状态 | 卡片行 | 是 |
| L2 时间线 | 它经历了什么（决定/计划/执行/验收） | 详情屏 | 是（四段折叠） |
| L3 证据 | 凭什么这么判（日志/diff/响应/文件） | 证据抽屉 / 历史 | 否（点开才加载） |

**规则**：上层不重复下层的细节；下层永远能回溯到 `traceId`。用户从任何入口看到一张卡，都能在 2 次点击内到 L2、3 次内到 L3。

## 1. 历史记录在哪里看（问题 1）

现状缺的是「**卡之外的历史**」：卡关掉后从列表消失，用户找不到"上周那张删表的卡后来怎么了"。

### 1.1 三种历史，分开看

| 历史 | 内容 | 入口 | 保留 |
| :-- | :-- | :-- | :-- |
| **卡历史** | 已关闭的卡（confirmed / failed / rejected / dismissed / notice） | 工作台「已关闭」分组 + 过滤 | 全量（可清理） |
| **案卷历史** | 一张卡的完整 `CaseEvent` 流水（谁在什么时候把它从 A 推到 B） | 详情屏底部「完整时间线」 | 200 条 trace（可配置） |
| **运行历史** | 观察者/决策/执行每次运行的记录（耗时、模型、产出、失败原因） | 「记录」屏 | 最近 500 条（可配置） |

### 1.2 入口设计

- 面板头部右上角常驻两个入口：`记录`（运行历史）与 `已关闭 N`（卡历史），不再藏在过滤里。
- 工作台过滤新增「已关闭」，与「全部 / 待决策 / 执行中 / 待验收 / 需关注」并列。
- 详情屏底部加「查看完整时间线」，从当前卡跳到该 case 的全部事件（含被折叠的中间态）。

### 1.3 记录屏（新）

```text
[记录]  筛选：全部 / 观察者 / 决策 / 执行 / 验收   时间：今天 / 7 天 / 30 天
─────────────────────────────────────────────
12:31  决策  c-42  批红 approve（delegated）  1.8s  tr-9f2c41d8ae07
12:32  执行  c-42  session adapter 失败 exit 1  184s  tr-9f2c41d8ae07
12:33  验收  c-42  机器项 2/3 → failed         0.2s  tr-9f2c41d8ae07
12:35  决策  c-43  升级用户（destructive）     2.1s  tr-3b8e02f1c55a
```

- 每行可点：跳到对应卡详情（或该卡的时间线锚点）。
- 支持按 `traceId` / 卡 id / 会话 id 搜索，支持复制一行。
- 这是排障的第一入口：用户报"它没动"，先在这里看是**没被建卡**、**没被批**、**没被派**、还是**判了但没通过**。

### 1.4 数据要求

- `CaseEvent` 必须含：`caseId / traceId / phase / actor / authority / from / to / reason / policyVersion / at`。
- 运行记录复用现有 `records.json`，加 `caseId` 与 `traceId` 两个字段，才能和卡对上。
- 保留策略在设置页可调；清理只删 L3 证据，不删 L2 事件摘要。

## 2. 同一会话的卡片怎么区分（问题 2）

根因：卡片行没有**会话身份**，同会话多张卡只看标题像一组孤立的卡。

### 2.1 三条区分线索（同时给）

1. **会话键**：卡片行显示 `会话短码`（如 `s-7d31`）+ 会话标题，同会话的卡共享同一个短码。
2. **轮次/时间**：显示「第 N 轮 · 12 分钟前」，同一轮产生的卡按创建顺序排列。
3. **来源卡**：如果是某张卡的后续（补跑/返工），标注 `源自 c-42`，形成链而不是重复。

### 2.2 分组视图（默认）

工作台默认按会话分组，组头是可折叠的：

```text
▾ 会话 s-7d31 · 调度器设计：卡片生命周期 · 3 张卡 · 2 待处理
    c-42  失败   跑测试并提交 feat/scheduler 分支
    c-46  排队   补 scheduler 单元测试
    c-51  未知   重跑 lease 过期用例并核对
▸ 会话 s-2a90 · 数据清理 · 1 张卡
```

- 组头显示：会话标题、卡数、待处理数、最近活动时间；点组头折叠。
- 组内排序沿用 `compareCards`（决策 → 知晓 → 自动 → 已结束）。
- 视图过滤切换时保留分组，不把组打散。
- 平铺视图保留为选项（工具条 `按会话 / 平铺`），给批量处理场景。

### 2.3 同会话内避免"看起来重复"

- 同源去重：同一会话同一轮、同 kind、同标题的卡只留一张（P0b 已列）。
- 后续卡显式标 `源自 c-42`，不合并、不覆盖；用户能看到"这是一次返工"。
- 卡片行右侧给「会话内序号」`#2/3`，避免同名卡混淆。

## 3. 验收规则与秘书权限（问题 3）

### 3.1 验收规则：可增删，但要"可试运行、可回滚"

成熟做法：**模板库 + 单卡覆盖 + 版本化**（policy as code 的产品化，不是让用户写代码）。

| 能力 | 交互 | 约束 |
| :-- | :-- | :-- |
| 增 | 「新建模板」→ 选卡类型（提交代码/部署/通知/自定义）→ 逐条加 criterion（machine/evidence/manual + 表达式 + verifier） | 表达式做语法校验；machine 项必须给"如何取证据" |
| 删 | 模板行 `…` → 删除 | 被使用中的模板删除时提示"仍有 N 张卡引用"，可选归档 |
| 改 | 就地编辑 + 「试运行」：用最近 20 张卡回放，显示"会从此通过变失败"的卡 | 改完生成新版本号，不改历史卡 |
| 单卡覆盖 | 详情「计划」段 → 改验收标准 → 生成**新卡**（需重新批准） | 已执行的标准不可原地改，防止事后合理化 |
| 回滚 | 模板版本列表 → 回到 v2 | 回滚只影响之后的新卡 |

### 3.2 秘书权限：可放大缩小，但"上限锁死 + 变更留痕"

用**授权矩阵**而不是一堆开关：行是 `effect`（read / write-code / destructive / external / spend），列是三档授权。

| effect | 可选项 | 默认 | 硬上限 |
| :-- | :-- | :-- | :-- |
| read | 秘书自动 / 秘书批 / 我批 | 秘书自动 | 可全委派 |
| write-code | 秘书自动 / 秘书批 / 我批 | 秘书批 | 可全委派（写操作不自动重放） |
| external | 秘书批 / 我批 | 我批 | 不允许"自动" |
| spend | 秘书批 / 我批 | 我批 | 不允许"自动" |
| destructive | 我批（仅） | 我批 | **不可委派** |

另外两个旋钮：

- **置信阈值**：`confidence < 0.70 → 升级`（可调 0.5–0.95）。
- **无判例时**：`升级 / 给建议后升级 / 按同行规则`（默认给建议后升级）。

**防误操作**：

1. 放大权限（任何一行从"我批"改成"秘书批/自动"）→ 弹确认，写明影响面（"今后 external 不再找你，本周约 3 次"）。
2. 每次变更写一条 `policy_change` 事件：谁改的、改了什么、旧值新值、生效时间。
3. 提供「试运行 7 天」：只记录"如果按新规则会怎样"，不改真实派发。
4. 破坏性上限不可解除；要用必须改代码/配置，不走 UI。

### 3.3 页面落位

- 「策略」屏拆成三块：**授权矩阵** / **验收模板库** / **升级预览**（右侧实时显示"按当前规则，哪些卡会来找你"）。
- 设置与策略分开：策略是"怎么判"，设置是"开不开、跑多快、留多久"。

## 4. 插件设置页（问题 4）

### 4.1 分区（六组，按使用频率排）

| 组 | 关键项 | 交互要点 |
| :-- | :-- | :-- |
| **总开关** | 插件启用 / 观察者 / 决策者 / 执行器 | 每个都有独立开关；关掉执行器 = 只出卡不动手 |
| **决策者** | 启用、模型、提示词、**暂停（只建卡不批）**、置信阈值 | 暂停时工作台顶部横幅提示"秘书已暂停，N 张卡在等" |
| **执行** | 自动执行（read/write-code）、仅会话执行、并发上限（WIP） | WIP 默认 1，改大有风险提示 |
| **预算与超时** | 单卡超时、单次运行 token/时长上限、每日上限 | 超限行为可选"降级为等待"或"升级给我" |
| **保留与隐私** | trace 保留条数、证据保留天数、卡片内容脱敏 | 清理是后台任务，有"上次清理"时间 |
| **通知** | 侧栏徽标、实时/摘要、静默时段 | 摘要模式：每小时合并一次 |

### 4.2 "中断限制"怎么表达

用户说的"中断"有两种，分开做：

1. **暂停决策者**（不再自动批）→ 设置页一个开关，语义是"卡继续建，票不再出"。
2. **停止执行器**（不再派发）→ 独立开关，语义是"已批的卡排队等你恢复"。

暂停不丢数据：恢复时给两个选项——**继续排队**（默认）或**丢弃已过期计划**（超过 TTL 的 plan 标记 cancelled）。

### 4.3 危险操作统一模式

- 破坏性开关（关插件、清空数据、改 WIP 上限）用**红色区块 + 二次确认 + 输入确认词**。
- 所有设置变更写审计事件，可在「记录」里按 `setting_change` 过滤。

## 5. 会话内介入开关（问题 5）

### 5.1 形态：输入框上方的一枚常驻 chip

```text
┌───────────────────────────────────────────────┐
│ 任务卡：自动 ▾        [本轮不介入]             │
└───────────────────────────────────────────────┘
```

点开是三档 + 作用范围：

| 档位 | 行为 | 适用 |
| :-- | :-- | :-- |
| **自动**（默认） | 观察者建卡、秘书批、按策略执行 | 日常 |
| **仅记录** | 只建卡、不批不执行（攒着给你看） | 调试、敏感会话 |
| **关闭** | 本轮/本会话完全不介入（不建卡、不投递） | 临时对话、贴密钥排查 |

作用范围：`本会话` / `接下来 1 小时` / `仅本轮`；选择后 chip 变色并显示剩余时间。

### 5.2 交互细节

- 键盘：`⌘/Ctrl + .` 打开 chip 菜单，`Esc` 关闭；不改当前输入内容。
- 关闭时**已经在跑的 plan 不打断**，只停止新派发；chip 上显示"1 张卡执行中，完成后停止"。
- 恢复时给 toast：「任务卡已恢复；期间错过 2 张卡，已列在工作台」。
- 会话里记一条系统提示（可见）：`〔任务卡：本会话已关闭介入〕`，避免用户忘了自己关过。

### 5.3 数据要求

- 会话级覆盖存 `sessionOverrides`（sessionId → mode + expiresAt + scope），优先级高于全局设置。
- 覆盖变更写 `CaseEvent(phase=policy, actor=user, reason=override)`，可在记录屏追溯。

## 6. 会话里的任务卡回复节点（问题 6）

### 6.1 节点长什么样

现有实现已有 `taskCardAnswer` 节点，需要补的是**可点、可回溯**：

```text
┌────────────────────────────────────────────────────┐
│ 任务卡 · 已批准                    12:31  c-42  ↗  │
│ 跑测试并提交 feat/scheduler 分支                    │
│ 秘书批（delegated）· 验收中 2/4                     │
│ [查看卡片详情]                                      │
└────────────────────────────────────────────────────┘
```

- 必显：卡标题、决定（批准/拒绝/答复）、谁批的、当前阶段、时间、卡 id。
- 失败/未知时节点变红/灰紫，附一句原因：「执行失败：2 个用例未通过」+ `去排查`。
- 卡片已关闭时节点保持只读，仍可点开看完整时间线。

### 6.2 点击行为

1. 主点击（标题区）→ 打开 **900px 卡片详情模态**（复用面板详情屏，不新做一套）。
2. 右上 `↗` → 在面板里打开（跳工作台并选中该卡），用于"我要看完整链路"。
3. 模态内可继续跳到失败排查 / 证据抽屉 / 复制 trace，形成闭环。
4. 关闭模态后焦点回到节点，键盘可达。

### 6.3 数据要求

- 节点消息需持久化 `cardId`（已有）+ `traceId` + `stage` 快照，避免卡删了节点就断链。
- 节点渲染只读，不触发派发；任何动作都在详情模态里做。

## 7. 我还看到的问题（补充建议）

| # | 问题 | 建议 |
| :-- | :-- | :-- |
| 1 | **等待没有 ETA** | 每个 `waitReason` 给"预计还要多久 / 等谁"，没有 ETA 就写"不确定，等会话空闲" |
| 2 | **空态与首次使用** | 新用户第一次打开：三条引导（观察者会建卡 / 秘书会代批 / 你能随时接管） |
| 3 | **批量操作没有撤销** | 批量否决后 5 秒内可撤销（toast + undo），避免手滑清空 |
| 4 | **列表规模** | 卡片 >200 张时虚拟滚动或分页 50；分组折叠默认收起已关闭组 |
| 5 | **通知节制** | 侧栏徽标 + 摘要模式 + 静默时段；通知类不重复弹 toast |
| 6 | **权限变更的误用** | 放大授权必须二次确认 + 7 天试运行 + 审计；提供"一键回到默认" |
| 7 | **多会话/多工作区** | 工作台顶部加工作区切换；跨会话卡不混排 |
| 8 | **卡内容与聊天边界** | 卡片里出现密钥/路径时默认脱敏，详情里"显示原文"需一次点击 |
| 9 | **失败文案可读性** | 面向用户的一句话结论（"测试没过，2 个用例红"）+ 面向工程师的证据链接，两行都要有 |
| 10 | **i18n 与时区** | 时间统一本地时区 + 相对时间；文案全部走字典（现有约定） |
| 11 | **无障碍** | 状态不能只靠颜色：徽标文案 + 形状；键盘可达；`prefers-reduced-motion` |
| 12 | **数据导出** | 单卡可导出 JSON（含事件与证据），便于报障和留档 |

这些不都要进 A-core；建议 **1/2/3/9/11 进 M3**，其余进 M4 或之后。

| # | 标准 | 怎么验 |

## 9. 与 A-core 的映射

| 交互 | 依赖字段/事件 | 阶段 |
| :-- | :-- | :-- |
| 历史/记录 | `CaseEvent`、`records.json` 加 `caseId/traceId` | M0–M1 |
| 会话分组 | `Card.origin.sessionId` + 会话标题 | M3 |
| 模板 CRUD / 授权矩阵 | `policy.json` + `policyVersion` + `policy_change` 事件 | M2–M3 |
| 设置页 | `settings.json` 扩展 + 审计事件 | M3 |
| 会话内 chip | `sessionOverrides` + policy 事件 | M3 |
| 卡节点 | 节点持久化 `cardId/traceId/stage` + 详情模态复用 | M1（节点可点）→ M3（跳转） |
